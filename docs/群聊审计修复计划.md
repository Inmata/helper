## 2. 方案

### A. 主动发言

1. 默认 `threshold_percent` 改为 50。dev/holdout 已有评测数据：阈值 0.5 时误发言 6.7% / 6.7%，召回 60% / 70%；0.6 时为 2.9% / 4.4%，52% / 70%。连续发言加罚 0.1 不变。
2. WAIT 复判，参考 MaiBot 的 planner：其 wait 表示等一会儿再判断。判断结果是 WAIT 时，本群挂一个复判项，`wait_recheck_seconds`（默认 20，范围 5–120）后若本群版本未变（期间没有群友新消息）就再判断一次。这样“有人问了没人回”的时长会变长，`reply_unanswered` 才有机会升上去。每一轮最多复判 1 次，复判再得 WAIT 按 skip 处理。期间有新消息、艾特或卸载时，作废复判，照常进入新一轮。复判仍要先过预算 `check`。
3. 默认 `start_hour` 改为 0，全天允许事件驱动主动发言。定时候选（`memory/hourly.py`）的窗口不动。
4. Jev 提示词里“87% 沉默”那句不改：改了就要重新跑一遍评测，本次不做。

### B. 引用回复与手打艾特

**B1 实测样本采集（先做，决定 B2 的实现细节）**

用户已授权 Lead 自行重启机器人测试，不需要人工发消息。所以不需要手动探针消息，改为被动采集：

1. 原生层放行 appmsg 57 且含 `<refermsg>` 的 type 49 消息，正文缓冲同时扩到 8KB。
2. Python 侧收到引用消息后，把原始 XML（截断到 8KB）追加写入 `.runtime/quote_probe.jsonl`，每条一行，文件上限 40 条/1MB。这是临时诊断，验证完成后删除该写入与文件。
3. 群里本来就有引用回复的流量（10-28 的 #12233 一类），重启后等自然样本即可确认：
   - 正文是否带 `wxid:\n` 前缀；
   - XML 是否装得进 8KB；
   - 引用是机器人自己时 refermsg 的 `chatusr`/`fromusr` 是否等于本账号；
   - 引用加艾特时 msgsource 里有没有 atuserlist（没有的话，手打 @ 与引用两条都要靠 B3）。
4. 同时发一条启动公告，请群友引用机器人或手打 @ 试一下，缩短等待。

**B2 接收引用消息**

1. 原生层放行 appmsg type 57 且含 `<refermsg>` 的 type 49 消息；链接、文件、转发等其他 type 49 消息仍然丢弃。
2. 新增 `WxPollTextMessageV3`，扩大正文缓冲（按 B1 实测长度定，至少 8KB）；V1 的 1312 字节和 V2 的 5408 字节边界不变。
3. Python 侧用与 `parse_at_members` 相同的安全解析（拒绝 DOCTYPE/ENTITY）解析 XML，字段参照开源项目 diting 的 `xml_parser.py` 和 WeChatMsg 的 `parser_reply`：
   - 回复正文取 `<title>`，作为消息文本，按 type 1 交给下游；
   - 被引用的内容放进 `data["quote"] = {wxid, name, type, text}`，其中 `text` 只在 refermsg type 为 1（文本）时取，截到 300 字。
4. 数据库 `messages.text` 只存回复正文，不改表结构。

**B3 艾特判定**

满足以下任一条，即算叫机器人：
- 真实结构化艾特（现状）；
- 正文含 `@<机器人名>`，名字后面跟 ` `、空格、标点或正文结束。机器人名的来源有三个：
  - 微信昵称；
  - 新配置 `mention_aliases`（如 `["有个ai"]`）；
  - 本次运行中真实艾特消息里出现过的艾特标签（自动学习）；
- 引用的是机器人自己的消息（refermsg 的发送者是本账号），满足 twT 10-27 17:47 的需求。

命中时补上 `is_at_self` 和 `at_members`，并标记 `at_source = structural / typed / quote`。主动发言插件随之把它当作艾特处理，清掉本群待判断项。

**B4 回复里看得见引用**

艾特回复的输入新增【引用】小节：“被引用者：内容”。SYSTEM 补一句：提问引用了别的消息时，结合被引用内容回答。

### C. 拆分残句

只有一句、按逗号切开的闲聊拆分，整句一起发完，不因插话丢弃后半句：仍有条间隔，但不做插话检查，`InterjectionGate` 不 arm。按句末标点切开的拆分保持现有行为。艾特回复和主动发言都经 `utterance.speak`，一处修改两处生效。

### D. 重复回复

1. SYSTEM（艾特）和 PROACTIVE_SYSTEM 补一条：不要重复自己最近几条回复的开头、称呼句式和调侃角度；同一人连发几条时，针对这一条的内容回应。
2. 代码检查：生成后与本群机器人最近 5 条发言比较，两条判据任一命中就算相近：
   - 开头 4 个字相同；
   - 字二元组 Jaccard ≥ 0.5。

   相近时带上“和你刚说的『…』太像，换个角度”的提示重试一次；仍然相近就照常发送，只记日志，不额外拖延。

### E. 时间感知

1. 艾特回复的输入新增【当前时间】，如“10-28 00:52（深夜）”。时段划分：
   - 0–5 深夜
   - 5–8 清晨
   - 8–11 上午
   - 11–13 中午
   - 13–18 下午
   - 18–23 晚上
   - 23–24 深夜
2. SYSTEM 补一句：说早晚、白天黑夜时以【当前时间】为准。
3. 主动发言生成的输入同样带上当前时间。
