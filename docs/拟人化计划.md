# 微信群机器人拟人化：实施计划

修订日期：2026-10-27。状态：步骤 1 已完成并在群内试运行（2026-10-27）；步骤 2、3 未开始。RAG 计划暂缓，见 [RAG接入计划.md](RAG接入计划.md)。

## 1. 问题与现状数据

用户提出的三个问题是：只在被艾特时说话，定时发言效果一般；单条发言太长；“损友”人格太单薄。群里的直接反馈有 #9499“ai 味能再浓点不”（回应 #9497），以及 #8749–8751“感觉这个ai还是不太自然 / 幽默感不够 / 人格相关的工作做的比较少”。

下表来自 `.runtime/member_data.sqlite3` 的只读统计：

| 指标 | 机器人 | 群友 |
| --- | --- | --- |
| 单条长度中位数 | 106 字 | 9 字 |
| 单条长度 p90 | 206 字 | 22 字 |
| 含空行分段的消息占比 | 52.8% | 0.3% |

机器人的“AI 味”主要不是通用 ChatGPT 用语，而是一个固定套路：先接梗，再认真解释，最后用“你这…是吧 / 赶紧…”收尾。现有长度约束只是软目标：`dialogue.py` 的 SYSTEM 写着“闲聊约50—120个汉字”。按 6243c4e 的经验，硬截断（例如 20 字）会明显损害质量。

## 2. 调研依据

| 来源 | 采用的结论 |
| --- | --- |
| [When2Speak](https://arxiv.org/abs/2605.05626) | 大模型在群聊中普遍说得太多，约 87% 的时机应保持沉默，所以默认动作应是不说 |
| [MultiLIGHT](https://arxiv.org/abs/2304.13835)、[Inner Thoughts (CHI 2025)](https://arxiv.org/abs/2501.00383) | 把“何时说”和“说什么”拆成两步；先给念头打分，过阈值才说 |
| [长度指令可靠性](https://arxiv.org/abs/2505.16234) | 单靠提示词控制长度不可靠，需要配合后处理和真实短句示例 |
| [人格效应](https://arxiv.org/abs/2503.23674) | 有具体人格时被判为真人的比例为 73%，无人格时为 21% |
| [MaiBot](https://github.com/MaiM-with-u/MaiBot) | 消息防抖（安静 2s、活跃 5s、最长 8s、艾特 1s）；planner 输出 reply / wait / stop；从群聊学习表达和黑话 |
| [AstrBot](https://github.com/AstrBotDevs/AstrBot) segmented_reply | 分段发送，段间隔 1.5–3.5s |
| pxchat、airi、SillyTavern talkativeness | 阈值随参与度动态调整，连续发言加罚；planner 允许返回空动作 |

结论：不采用“每 5 分钟固定 ReAct”的轮询方式，改为由消息事件触发。流程依次为：防抖，代码闸门，Jev 判断说不说，主模型生成，最后后处理成短句。

## 3. 步骤

按顺序实施。每步独立可交付，前一步通过后再开始下一步。

### 步骤 1：短句化与去 AI 腔（同时作用于艾特回复和定时发言）

1. 新增可重复运行的统计脚本 `tools/humanlike_metrics.py`，只读数据库，按时间段输出上表三项指标。脚本还要列出“机器人高频、群友几乎不用”的短语，排序依据为机器人频率与群友频率之比，并设最小出现次数。去 AI 腔的词表由这份输出生成，不靠人工挑词。
2. 回复分三档：
   - 闲聊/接梗：模型写 1–2 句。只有总长 ≤40 字且每句都短时才拆开，最多 3 条，条间隔 1–3 秒（按字数取值）。
   - 普通问答：单条发送，目标 ≤60 字，不拆。
   - 明确要求详细（沿用 `DETAIL_HINTS`）：保持现有长文和按 1023 字节分段的方式。
3. 硬规则：
   - 拆分最多 3 条。
   - 问答类不拆。
   - 拆分发送途中如果群里有别人发言，剩余条目丢弃。
   - 不做字数硬截断。
4. 改写 SYSTEM 和人格提示：
   - 去掉“50—120 字”的长度描述，改为“像群友一样说话”。
   - 附 8–12 条从本群挑出的真实短句作为 few-shot，挑选时排除地狱梗和家人梗。
   - 写入数据统计得出的套路禁用项，例如“先接梗再解释再收尾”的三段式和空行分段。
5. 定时发言（`memory/hourly.py`）的 30—80 字要求同步改为短句档。

过关条件：

- 回放最近 50 条非详细艾特提问，离线生成：长度中位数 ≤30 字，p90 ≤70 字，空行分段占比 ≤5%，词表短语命中率较基线下降一半以上。
- 用户在群里实测约 2 分钟（艾特几次），用统计脚本复测这段时间的机器人发言，结果与离线一致。
- 详细档回答完整、不被截断。
- 现有测试全部通过，新增拆分、丢弃、不拆问答的单元测试。

实施结果（2026-10-27）：

- 离线回放 50 条：长度中位数 26 字（基线 84.5），p90 45（基线 200），空行分段 0%（基线 28%），词表短语命中 0%（基线 40%）。
- 群内试运行约 5 分钟，9 次艾特：机器人中位数 30 字，p90 39，空行 0%；群友同期中位数 10。数值达标，但 9 条回复都是单句（模型用逗号连成一句），闲聊拆分一次也没有触发。随后两处都改：提示词要求两句之间用句号断开；只有一句时退而在逗号处切（每段仍 ≤20 字、总长 ≤40）。
- 第二轮试运行约 5 分钟，5 次艾特机器人：6 条消息，中位数 18.5 字，p90 29，空行 0%；拆分触发 2 次，其中 1 次因群友插话丢弃剩余 1 条，均按设计工作。
- 与原计划的偏差：
  - 问答超过单条容量时按容量分段，不截断（原计划“问答不拆”只覆盖正常长度）。
  - 插话检查分两次：间隔后预检，发送前在 `delivery_guard` 内复检；发送层打字延迟期间到达的消息只能在下一条前看到。
  - 除疑问词外，“解释、推荐、帮我、对比”等请求词也归为问答档。

### 步骤 2：从群聊归纳人格

1. 以现有“熟人损友”提示为基准，补充以下设定：年龄二十多岁，职业不明，爱好从群聊中归纳。
2. 归纳脚本从近期群聊统计口头禅、句尾语气词、表情/颜文字用法、高频梗和当前话题，生成人格补充草案。草案只学节奏、口癖和梗，不学具体的冒犯内容。群里常见的死亡梗、家人梗不进入草案，现有安全禁则全部保留。
3. 草案自动生效，不经人工审核（用户已确认）。为此加两道保护：
   - 生效前用代码过滤和 Jev 对草案做安全筛查，命中冒犯类内容的条目直接丢弃。
   - 每版都留存，控制台可一键回退到上一版或基准。

过关条件：

- 基准人格与新人格各生成 30 条盲评样本，由用户判断哪条更像群友，新人格胜率 ≥60%。
- 安全禁则相关的现有测试（`tests/test_personality.py`）通过。
- 草案中不含被排除的冒犯类内容。

### 步骤 3：事件驱动的主动发言（Jev 判断）

1. 新插件 `plugins/proactive_chat`，运行在插件自己的 `Plugin.proactive_chat` 线程上，不新增 memory 后台线程。
2. 防抖：按群合并新消息，安静 3 秒或累计满 8 秒后处理一批。艾特消息仍由 mention_chat 即时处理，不经过这里。
3. 代码闸门按顺序检查，任一条不满足就不发言，也不调用模型：
   - 每群滑动 10 分钟最多 5 次主动发言。一次拆分发送算 1 次，艾特回复不计入。
   - 两次主动发言至少间隔 60 秒。
   - 没有群友插话时最多连续主动发言 2 次。每次连续发言把阈值提高 0.1。
   - 机器人发言后至少有 1 条群友新消息，才开始下一次判断。
4. Jev 判断：
   - 输入：最近约 15 条消息、机器人上次发言距今多久、是否有人提到机器人（未艾特，比如说“ai”“机器人”）、人格摘要。
   - 问法：choice 题型，选项为 reply / wait / skip，附明确 criteria。
   - 只有 reply 概率 ≥ 阈值才进入生成。阈值由评测确定。
   - Jev 超时或失败一律视为 skip。
5. 生成时沿用步骤 1 的短句档和步骤 2 的人格。生成结果可以为空，空结果也视为 skip。发送时沿用 `delivery_guard`，记录 `record_bot_reply`。
6. 现有 `HourlyScheduler` 保留，但只在冷场时触发：该群一段时间内没有任何消息（含主动发言）才开话题，时长在实现时按数据定。功能用配置开关控制，默认关闭，评测达标后在用户唯一的群开启。

先评测再接入：

- 从真实群聊截取 ≥100 个片段。Lead 先预标“该说 / 不该说”，用户抽查并改正。
- Jev 判断在“不该说”片段上的误发言率 ≤10%，在“该说”片段上的召回率 ≥50%，单次耗时 p90 ≤2 秒。
- 已知风险：探索期对 2 个样本试测时，“收到/好的/明天九点开会”这类消息也被判为 reply（0.93），noul 值 0.54 与 0.47 区分不开。因此输入必须带上述上下文；评测不达标就不接入。

过关条件：

- 评测达标。
- 在群里实测数分钟：日志显示任意 10 分钟内主动发言不超过 5 次，没有刷屏。
- 统计脚本显示主动发言长度与步骤 1 的指标一致。
- 群友对主动发言的反馈由用户记录，作为人工验收。
- 单元测试覆盖：配额、冷却、连续发言惩罚、Jev 失败时 skip、艾特回复不计入配额。

## 4. 为完整 ReAct 预留的结构

完整 ReAct 不在本计划内实施，但本计划新写或重构的代码必须按下列接缝组织。这样以后加上工具调用和多轮循环时，只需新增实现，不必重构已有代码。

| 接缝 | 本计划的做法 | 以后 ReAct 怎么接 |
| --- | --- | --- |
| 决策 `Planner.decide(context) -> Action` | 步骤 3 的 Jev 判断是一个 Planner 实现；`Action` 为 `{type, args}`，现阶段 type 只有 reply / wait / skip | 新增一个调用模型和工具的 Planner，返回 `query_memory` 等工具动作，调用方不变 |
| 上下文 `ContextTools` | 把 mention_chat 里的 `knowledge.search` / `lookup_people` / `speaker_profile` / `style` 预取，收成一组带名字、参数和说明的函数；现在仍由代码一次性调用 | 同一组函数登记为模型可调用的工具，说明文字直接转成 tools 描述 |
| 发言 `utterance` | 分档、拆分、间隔、插话丢弃集中在一个模块；艾特回复、主动发言、定时发言都只通过它发送 | ReAct 循环的 reply 动作同样调用它，长度和防刷屏规则不会被绕过 |
| 模型接口 `LLMClient` | 只做增量：新增方法，不改 `complete_text` / `complete_json` 的签名和行为 | 新增 `complete_tools(messages, tools)` 解析 `tool_calls`（DeepSeek 等 OpenAI 兼容接口支持） |
| 预算与安全 | 配额、冷却、`delivery_guard`、快照过期按“每个发出的动作”检查，不绑死在某个调用位置 | 循环每走一步都套用同一套检查，并另加最大步数和总超时 |

Reviewer 审查每个工作包时都要对照本表，确认没有出现把这些逻辑写死在单个插件里的实现。

## 5. spec 影响

- 修改 `.spec/mention-reply/spec.md` 规则 3（长度）。改后验收句：“非详细提问按闲聊/问答分档：闲聊总长 ≤40 字时可拆成至多 3 条短句发送，问答单条发送且不拆；不做字数硬截断；回放 50 条非详细提问时长度中位数 ≤30 字、p90 ≤70 字。”
- 修改 `.spec/mention-reply/spec.md` 规则 4（分段）。改后验收句：“只有明确要求详细的回答按 1023 字节减去艾特前缀的预算分段；闲聊拆分最多 3 条、条间隔 1–3 秒，拆分发送期间群内出现他人新消息时丢弃剩余条目。”`code:` 增加实现拆分逻辑的文件。
- 新建 `.spec/proactive-chat/spec.md`，`code:` 包含 `plugins/proactive_chat/__init__.py`、`wxbot_framework/memory/hourly.py`。验收句：“主动发言由消息事件触发，先按群防抖；每群 10 分钟内至多 5 次主动发言，艾特回复不计入；两次间隔至少 60 秒，无群友插话时至多连续 2 次；Jev 判断 reply 概率达到阈值才生成，Jev 失败或生成为空时不发言；定时发言作为冷场兜底保留，长度遵循短句档。”
- 人格归纳落在 `.spec/learning` 或 `personality.py` 的哪个 spec，实现时按 `code:` 归属判断。若需修改 `.spec/learning/spec.md` 正文，先问用户。
- `.spec/delivery`、`.spec/architecture`：无。主动发言复用插件线程和现有发送接口。

## 6. 已确认的决定

| 项目 | 决定 |
| --- | --- |
| 主动发言配额 | 每群 10 分钟最多 5 条；艾特回复不计入 |
| 判断模型 | Jev（System One，`typesafe/jev-latest`，本机网关 `http://127.0.0.1:3425/v1`） |
| 人格基准 | 现有损友人格；年龄二十多，职业未知，爱好从群聊归纳 |
| 人格草案 | 自动生效，有安全筛查，可一键回退 |
| 评测标注 | Lead 预标，用户抽查改正 |
| 定时发言 | 保留，仅冷场时触发 |
| 试运行 | 用户唯一的群 |
